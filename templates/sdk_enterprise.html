The Problem

AI Pipelines Are Flying Blind on Event Integrity

Every AI workflow writes events. Almost none of them verify what was written, when, or whether it was tampered with in transit. You end up debugging ghosts.

Tampered Webhooks

Downstream consumers receive events with no digest. Any MITM or misconfigured proxy silently corrupts your audit trail.

Warehouse Drift

Batch exports accumulate without provenance. By the time you query them, you can't tell which records were clean at write time.

Session Blind Spots

Request-level signing stops at the HTTP boundary. AI agent actions that span multiple API calls have no verifiable lineage.

Compliance Gaps

Regulators ask for event integrity proofs. You have logs. Logs are not proofs. The gap is expensive to close at audit time.

How It Works

Four Steps. Deterministic Every Time.

Step 01

Event Fires

Your Flask route handles a request. VOID intercepts at the response layer.

Step 02

Al-Jabr 286 Stamps

Payload + session + timestamp are hashed to a 286-bit deterministic digest via Fatiha layers.

Step 03

Digest Delivered

The digest rides on the response header or webhook payload. Nothing extra to deploy.

Step 04

Receiver Verifies

Any downstream consumer recomputes the digest and compares. Pass or fail, deterministic.

FAQ

Questions from the CTO Review

Does this require a schema migration?
No. The digest rides on the response header or the webhook payload envelope. Your database schema is untouched. Warehouse exports write to new files, not existing tables.
What dependencies does the webhook guard add?
Zero new dependencies. build_webhook_payload() and post_webhook_payload() are implemented with Python's stdlib urllib only. The core hash runs on hashlib and hmac.
Is the hash reversible or claimable as a standard?
No. Al-Jabr 286 is a deterministic, one-way digest function. VOID does not claim to be an HTTP-equivalent web standard. Conformance V1 defines an integration contract for VOID-compatible systems only.
How do receivers verify a webhook without a shared secret?
The digest is computed deterministically from the payload itself — no shared secret is required for the base verification. For environments that require HMAC-style signing, the SOVEREIGN tier adds a per-node Ed25519 signature layer.

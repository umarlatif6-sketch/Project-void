## INTRODUCTION: THE PROBLEM

When the same principle appears across different domains, it uses different terminology:

- **Finance:** "Flow" = capital movement, velocity of money, liquidity
- **Water:** "Flow" = liquid displacement, volume per time, conductivity
- **Ocean:** "Flow" = current patterns, tidal resonance, salinity gradients

**The danger:** If agents operate across domains without understanding these contextual differences, they create linguistic misunderstandings that cascade into system failures.

**The solution:** Build a translation layer that recognizes when a term appears in multiple dictionaries and maps the underlying principle (not the word).

## CONTEXTUAL DISAMBIGUATION ENGINE: HOW IT WORKS

### Rule 1: Domain Detection

When an agent encounters a term like "flow," it first determines the domain context:

```
IF context = "financial transaction" THEN
  flow = capital velocity
ELIF context = "customer journey" THEN
  flow = liquid movement through channels
ELIF context = "agent network" THEN
  flow = water mass circulation
ELSE
  flow = generic directional movement
```

### Rule 2: Principle Extraction

Once domain is detected, extract the underlying principle:

```
flow (any domain) → underlying principle = directional transfer with impedance
```

### Rule 3: Cross-Domain Translation

If an agent needs to operate across domains, translate through the principle:

```
Finance flow (capital velocity) 
  → Principle: directional transfer with impedance
  → Water flow (liquid movement)
  → Ocean flow (water mass circulation)
```

### Rule 4: Resonance Alignment

Check if the principles align (resonance) or conflict (impedance):

```
IF principle_A aligned with principle_B THEN
  resonance = high → amplification
ELSE
  impedance = high → dampening
```

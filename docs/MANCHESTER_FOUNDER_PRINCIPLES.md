# PROJECT VOID — FOUNDER PRINCIPLES

## Manchester Doctrine Card

These principles are the leadership baseline for Project VOID under scale, pressure, and handoff.

1. Build so that trust is measurable, not assumed.
2. Preserve origin at every handoff.
3. Enforce governance where decisions move, not where reports are written.
4. Favor fail-closed defaults over convenient ambiguity.
5. Treat every artifact as memory with accountability.

## Founder Statement

Trust is a sacred intention, but in systems it must be measurable. Anything unmeasured becomes mythology. Anything unverifiable becomes vulnerability. So we build for proof, not assumption. That is how trust survives scale.

## Operational Translation

- Signed manifests over verbal assurance
- Sector ACL over implicit permissions
- Freshness windows over stale replay risk
- Append-only audits over retroactive storytelling
- Chronicle continuity over session amnesia

## Closing Line

Project VOID does not optimize for belief. It optimizes for verifiable continuity.

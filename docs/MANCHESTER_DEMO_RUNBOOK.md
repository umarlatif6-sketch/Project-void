# PROJECT VOID — MANCHESTER DEMO RUNBOOK

## Objective

Run one clean path that feels inevitable.

The demo should show:

- the system can read behavior
- the system can secure hidden payloads
- the system can be explained in institutional language afterward

## Demo Sequence

### Demo 1: Resonance Read

Goal:
Show that Project VOID is not abstract. It responds live to human interaction.

Run:

1. Open the live app.
2. Ask the person to scroll normally for 30 seconds.
3. Let the reading complete.
4. Show the resulting signature, archetype, and track.

Line:
This is the front door. The system is reading interaction, not just waiting for prompts.

### Demo 2: VoidEcho Decode

Goal:
Show that sensitive material can be hidden and recovered inside ordinary audio.

Run:

1. Open the prepared audio file.
2. Play a short segment.
3. Ask: does this sound like normal audio?
4. Open the decode flow.
5. Recover the hidden document.
6. Stop talking and let the moment land.

Line:
The document was inside the audio the entire time. That is the transmission layer.

### Demo 3: Security Bridge

Goal:
Translate the wow moment into institutional value.

Say:
Behind the demo, the system now uses signed packet manifests, sector-level access control, replay windows, and audit logs so agent communication and artifacts are policy-aware by default.

## Demo Timing

- Resonance read: 30 seconds
- VoidEcho decode: 45 seconds
- Security explanation: 30 to 60 seconds
- Total ideal flow: 2 minutes

## Rehearsal Standard

A demo is ready only if you can perform it three times in a row without hesitation, navigation errors, or explanation drift.

## Device Checklist

- Phone fully charged
- Power bank packed
- Demo app bookmarked
- Hidden audio file saved locally on phone
- Any required keys or sample files available offline
- Mobile data confirmed working
- Audio playback volume tested

## Failure Plan

If the live app stalls:
- pivot directly to VoidEcho
- say the behavioral read is the front door, but the transmission layer is the core infrastructure

If VoidEcho decode fails:
- show the prepared output artifact
- explain the packet security model and move to institutional framing

If connectivity is poor:
- use only local assets on device
- avoid depending on venue Wi-Fi

## Demo Rules

- Do not over-explain before the reveal.
- Do not mention every subsystem.
- Do not sell five markets at once.
- Let the proof come first.
- Explain only after they ask why it matters.

## End State

The person should leave with one belief:

This is not a concept deck. This is a live system with a defensible architecture.

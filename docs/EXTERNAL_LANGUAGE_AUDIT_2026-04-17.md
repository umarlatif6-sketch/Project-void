# External Language Audit

Date: April 17, 2026

## Purpose

This note records a repo-wide first pass to reduce legal, investor, and commercialization risk from overly absolute wording in Project VOID documents.

The rule used in this pass was simple:

- preserve architectural meaning,
- preserve Project VOID naming,
- remove unsupported certainty,
- distinguish measured results from modeled scenarios,
- and convert novelty claims into candidate or counsel-review language where appropriate.

## Normalized Claim Types

The following claim patterns were rewritten where they appeared in active external-facing documents:

- `unfakeable` -> stronger anti-spoof or biologically anchored
- `unforgeable` -> tamper-evident or provenance-oriented
- `patent-worthy` -> candidate claim direction or counsel-review candidate
- `the only platform` -> not identified in this public-source review
- hard revenue numbers -> illustrative scenarios unless booked or measured
- universal superiority language -> narrower, domain-specific differentiation

## Archival Material

Some historical or chronicle-style files still contain strong rhetoric, especially:

- `VOID_CHRONICLE.md`
- `VOID_CHRONICLE_EXPORT.md`
- library collection books and narrative doctrine files
- vault or manifesto-style export artifacts

These files function partly as historical record, doctrine, or narrative archive rather than diligence-safe external briefing material. They should not be reused directly for investors, partners, counsel, or contracts without a fresh wording pass.

## Recommended External-Use Rule

For external use, prefer these document families first:

- `docs/ADRIANA_*`
- `docs/VOID_FIELD_MANUAL/*`
- `docs/MANCHESTER_*`
- `COST_SAVINGS_ANALYSIS.md` after scenario language review
- `IP_DISCLOSURE.md` only as counsel-prep material, not as final legal conclusion

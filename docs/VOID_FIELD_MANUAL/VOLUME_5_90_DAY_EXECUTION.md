# Volume 5 - 90-Day Execution Volume
## Convergence Sprint Blueprint

Purpose:
- Translate field vision into a 90-day execution system.

---

## 90-Day North Star

North star outcome:
- One wedge workflow with validated reliability, controlled cost, and clear buyer value.

Primary constraints:
1. Reliability before expansion.
2. Proof before narrative scale.
3. Cost control before traffic scale.

---

## Phase 1 (Days 1-30): Stabilize The Loop

Objectives:
1. Lock system boundaries.
2. Reduce operational variance.
3. Finalize benchmark suite.

Deliverables:
- D1: Benchmark baseline report.
- D2: Failure taxonomy and alert thresholds.
- D3: Chronicle governance policy.
- D4: Wedge workflow definition.

Success criteria:
- Critical path success rate reaches target range.
- Every major failure class has documented mitigation.

---

## Phase 2 (Days 31-60): Prove Buyer Value

Objectives:
1. Run guided pilots.
2. Capture measurable business outcomes.
3. Tighten GTM language to match evidence.

Deliverables:
- D5: Pilot onboarding playbook.
- D6: Outcome dashboard per pilot.
- D7: Pricing and packaging revision.

Success criteria:
- At least one pilot with clear measurable outcome.
- Reduced demo-to-pilot friction.

---

## Phase 3 (Days 61-90): Package The Category

Objectives:
1. Publish category and proof artifacts.
2. Convert internal language to external clarity.
3. Prepare fundraising or scaled commercial outreach.

Deliverables:
- D8: Category brief public version.
- D9: Benchmark pack public version.
- D10: 2-3 case narratives with metrics.

Success criteria:
- External evaluators can replicate core proof.
- Team can deliver category pitch consistently.

---

## Weekly Sprint Format

Every week:
1. Monday: plan + risk declaration.
2. Tuesday-Wednesday: build + benchmark.
3. Thursday: integration + review.
4. Friday: publish internal brief + next lock.

---

## Daily Execution Card

Each day answer:
1. What did we prove today?
2. What broke today?
3. What did we learn today?
4. What is locked for tomorrow?

---

## Budget Envelope Template

Monthly cap buckets:
1. Inference and model calls.
2. Infrastructure and storage.
3. Monitoring and operations.
4. Pilot support and implementation.

Control rules:
- If inference spend exceeds threshold:
  - route to lower-cost models for non-critical tasks.
  - freeze exploratory experiments for 72 hours.

---

## Risk Register (Must Maintain)

Risk classes:
1. Technical reliability risk.
2. Security/compliance risk.
3. Cost overrun risk.
4. Narrative mispositioning risk.
5. Team throughput risk.

Each risk includes:
- owner
- severity
- trigger
- mitigation
- review date

---

## 90-Day Final Review

At day 90 publish:
1. What is proven.
2. What is pending.
3. What is removed.
4. What scales next.

Closing line:
- "We scale only what survives measurement."

# Volume 4 - Public Launch Speech Manual
## The Category Broadcast Book

Purpose:
- Speak to market, press, and community with precision.
- Convert attention into trust through clear claims and public proof.

---

## Public Speech Structure (12 Minutes)

1. Minute 0-2: The Naming
- Name the category.
- Name what it is not.

2. Minute 2-4: The Problem
- Show where current systems break.
- Use one concrete scenario.

3. Minute 4-7: The Protocol
- Carrier -> Codon -> Chronicle -> Action.
- Explain as a loop, not a feature list.

4. Minute 7-9: The Proof
- Show benchmarks and outcomes.
- Avoid speculative claims.

5. Minute 9-11: The Invitation
- Who should build with this.
- Who should evaluate this.

6. Minute 11-12: The Seal
- One closing line that defines the field.

---

## Stage Script (Novel Cadence)

Opening:
- [inhale] "Tonight, we are not announcing a feature."
- [pause 2]
- "We are naming a field."
- [hold]

Core declaration:
- [inhale] "Resonant Steganographic Intelligence is the integration of transport, memory, and decision into one measurable loop."
- [pause 2]

Proof pivot:
- [inhale] "Do not trust the language alone."
- [pause 2]
- "Trust the benchmark."
- [hold]

Close:
- [inhale] "If this field is real, it will survive replication and scrutiny."
- [pause 2]
- "If it is not, it should fail quickly in public."
- [exhale]

---

## Press Handling Protocol

When asked broad questions, respond with:
1. Category definition in one sentence.
2. One validated benchmark.
3. One practical use case.

When asked speculative questions:
1. Mark as hypothesis.
2. State current validation stage.
3. Give date for next public evidence.

---

## Public Claim Tiers

Tier 1 - Proven:
- Publicly reproducible now.

Tier 2 - In Validation:
- Working internally with scheduled public benchmark.

Tier 3 - Exploratory:
- Not presented as external claim.

Rule:
- Never present Tier 2 or Tier 3 as Tier 1.

## Demo Segment Blueprint

Demo sequence:
1. Encode known payload.
2. Transmit through chosen carrier.
3. Decode and verify hash match.
4. Show Chronicle entry for traceability.

Audience memory line:
- "The signal was hidden, transported, recovered, and remembered."

## Launch Day Checklist

1. Category page published.
2. Glossary published.
3. Benchmark note published.
4. API or workflow reference published.
5. Contact channel for evaluators enabled.
6. Incident response team on standby.

---

## Post-Launch 7-Day Rhythm

Day 1-2:
- Handle incoming technical questions.

Day 3-4:
- Publish FAQ with corrections.

Day 5:
- Release first patch or clarification note.

Day 6-7:
- Publish first-week metric snapshot.
